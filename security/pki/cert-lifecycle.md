# Життєвий цикл PKI лабораторії

Рекомендована ієрархія: офлайн Root CA -> Intermediate CA -> окремі сертифікати брокера та пристроїв. Root private key зберігати зашифрованим поза пристроєм; Intermediate використовувати для повсякденного підпису; кожен пристрій отримує унікальний сертифікат із власним CN/SAN та обмеженим призначенням.

- Перед видачею перевірити CSR, серійний номер, ідентичність і профіль призначення.
- Строк пристрою зробити коротшим від строку Intermediate; термін і процедуру ротації задокументувати.
- Відкликання фіксувати у CA database, генерувати CRL та за потреби надавати OCSP-responder через довірений gateway.
- Резервні копії зашифрувати й перевіряти відновлення без копіювання приватних ключів у репозиторій.
- Для виробничої системи розглянути HSM/secure element та контрольований provisioning; шаблон OpenSSL тут лише навчальний.

Скрипт `generate-lab-certs.ps1` формує локальну лабораторну ієрархію, але не налаштовує production HSM, OCSP-сервер або інтеграцію з MQTT брокером.
