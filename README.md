# Практична робота 3.3 — Безпека IoT

Окрема робоча папка для третьої частини. За основу взято локальний симулятор з IoT3(2); реалізації TLS/PKI, secure boot та мережеві налаштування будуть оформлені як захисні лабораторні конфігурації. Методичка збережена поруч як вихідний матеріал.

## Структура

- `weatherstation/`, `web/` — базовий Python-емулятор і панель попередніх частин.
- `security/pki/` — параметри CA, випуск/відкликання сертифікатів та безпечне зберігання ключів.
- `security/mqtt/` — приклад mutual TLS, ACL і захисту повідомлень.
- `security/firmware/` — налаштування Secure Boot, підписаних оновлень і anti-rollback для ESP32.
- `security/network/` — схема сегментації та шаблон VPN/firewall.
- `security/audit/` — модель загроз STRIDE, локальний план перевірок і реагування.
- `practice-03-iot-protocols_part_3.pdf` — методичка; її не додавати до GitHub.

Ключі, паролі й готові приватні сертифікати не зберігати в репозиторії. Для фізичних функцій ESP32 знадобиться відповідна плата та відновлення через serial/JTAG до активації Secure Boot або Flash Encryption.

## openHAB

Сторінку openhab/iotpr3_security.yaml встановлено в локальну конфігурацію openHAB 5.2.3 (conf/yaml/iotpr3_security.yaml). Для відображення вбудованої панелі спочатку запустіть start_part3.bat; потім відкрийте сторінку з UID iotpr3-security у Main UI. Сторінка використовує oh-webframe-card і локальну адресу http://127.0.0.1:5002/security.


## Інтерактивна перевірка безпеки

На сторінці /security доступні локальна перевірка підпису HMAC-SHA-256 з відхиленням replay і підроблених повідомлень, а також статичний огляд шаблонів MQTT TLS, ACL та Secure Boot. Ці перевірки не вмикають TLS на брокері, VPN або Secure Boot на апаратурі; результати сторінка чітко відділяє від підготовлених конфігурацій. Кнопка перевірки викликає POST /api/part3/demo; результат огляду доступний на GET /api/part3/audit.
